# Storyboard PDS - Newsletter et qualité numérique

## Colonne vertébrale

Une adresse d’abonné circule entre trois lieux : le formulaire, la messagerie et le site. Le public suit cinq chapitres : s’informer et choisir ; confirmer et acheminer ; garder la maîtrise ; consulter et retrouver ; élargir, tester et mémoriser.

## Masque de série

Format 16:9, 1600 × 900. Fond blanc, panneaux `#F2F3F7`, bleu `#001070`, rouge `#E44850` réservé aux risques et états erronés. Marianne obligatoire, Arial uniquement si repli nécessaire. Illustrations plates à traits fins ; aucun faux logo, emblème, photo, dégradé, volume 3D ou blob. Titre à gauche ; badge `Règle N` à droite sur les slides de règle ; cinq segments de progression actifs sur les slides 3 à 18. Pied gauche `Opquast - présentation Miweb`, pied droit `Newsletter`. Un seul message central, trois à six libellés courts, aucun paragraphe. Les scènes et leurs compositions changent pour éviter le gabarit répété.

## Fiches des slides

### Slide 1 - Une newsletter, un service numérique complet

- Rôle : ouverture, montrer le service complet avant les détails.
- Scène : une enveloppe traverse un paysage éditorial en sept stations, sans couloir ni personnage dominant : panneau d’information, case vide, message à confirmer, boîte de réception, page Web, sortie, archives.
- Transformation : un courriel isolé devient un parcours suivi dans le temps.
- Texte exact : surtitre `Qualité numérique - Opquast V5` ; titre `Une newsletter, un service numérique complet` ; stations `Savoir` ; `Choisir` ; `Confirmer` ; `Recevoir` ; `Consulter` ; `Se désinscrire` ; `Retrouver`.
- Callout : aucun ; le titre porte déjà la thèse.
- Image seule : les sept moments appartiennent à la même expérience.
- Continuité : pose l’adresse comme fil rouge ; slide 2 place les neuf règles sur ce fil.
- Contraintes : sept stations distinctes, dans cet ordre ; aucune règle supplémentaire ; pas de répétition de la station d’entrée.

### Slide 2 - 9 règles au cœur de notre parcours

- Rôle : cadrer le périmètre sans le présenter comme exhaustif.
- Scène : carte en cinq ensembles, reliés par le même fil d’adresse : `Avant` avec 179 et 33 ; `Confirmer` avec 173 ; `Acheminer` avec 217 ; `Garder la maîtrise` avec 174, 175 et 176 ; `Consulter` avec 177 et 178.
- Transformation : neuf numéros deviennent une carte de service mémorisable.
- Texte exact : titre `9 règles au cœur de notre parcours` ; les cinq intitulés et neuf numéros ci-dessus.
- Callout : `D’autres règles transversales peuvent aussi s’appliquer.`
- Image seule : chaque règle appartient à une étape du parcours.
- Continuité : reprend les sept stations de l’ouverture ; lance le détail par l’information préalable.
- Contraintes : neuf numéros présents une fois chacun ; aucun numéro inventé ; ne pas faire une grille de neuf cartes.

### Slide 3 - Savoir avant de s’abonner

- Rôle : chapitre 1, rendre visible l’engagement avant la saisie.
- Règle : 179, `La fréquence d’envoi des newsletters est consultable avant l’abonnement.`
- Scène : gros plan d’une page d’abonnement ; le regard s’arrête sur la fréquence avant d’atteindre un champ d’adresse encore vide.
- Texte : titre `Savoir avant de s’abonner` ; labels `Fréquence annoncée`, `Adresse vide`, `Choix éclairé`.
- Preuve : `À vérifier : la fréquence avant toute saisie.`
- Continuité : après le cadrage, le public voit ce qui doit être su avant de choisir.
- Contraintes : ne pas inventer de fréquence chiffrée ; règle 179 exacte ; la fréquence est visible avant le champ.

### Slide 4 - Laissez l’utilisateur choisir

- Rôle : distinguer choix explicite et option préactivée.
- Règle : 33, `L’inscription à des services annexes n’est pas activée par défaut.`
- Scène : deux états d’une commande e-commerce ; à gauche, case newsletter précochée en rouge ; à droite, case vide que l’utilisateur choisit.
- Texte : titre `Laissez l’utilisateur choisir` ; labels `Précochée`, `Case vide`, `Action volontaire`.
- Preuve : `À vérifier : aucune inscription précochée au chargement.`
- Continuité : le savoir devient une décision concrète dans le contexte d’une commande.
- Contraintes : règle 33 limitée à l’inscription à un service annexe pendant la commande ; ne pas généraliser à tout formulaire.

### Slide 5 - Confirmer avant d’activer

- Rôle : montrer que l’adresse n’est pas abonnée avant confirmation.
- Règle : 173, `L’inscription aux newsletters est soumise à un processus de confirmation.`
- Scène : demande envoyée, message dans la boîte, action de confirmation ; le statut reste en attente jusqu’au clic.
- Texte : titre `Confirmer avant d’activer` ; labels `Demande`, `Courriel`, `Confirmation`, `Abonnement actif`.
- Preuve : `À tester : l’abonnement reste inactif avant confirmation.`
- Continuité : après le choix, l’utilisateur prouve qu’il maîtrise l’adresse.
- Contraintes : l’état actif apparaît seulement après l’action ; ne pas confondre accusé de réception et activation.

### Slide 6 - Authentifiez le domaine d’envoi

- Rôle : rendre visible la couche technique qui soutient la confiance et la délivrabilité.
- Règle : 217, `Le domaine de messagerie est authentifié`.
- Scène : un courriel traverse trois contrôles clairement nommés `SPF`, `DKIM`, `DMARC`, puis rejoint une boîte de réception ; une voie secondaire signale un risque de classement en spam.
- Texte : titre `Authentifiez le domaine d’envoi` ; labels `SPF`, `DKIM`, `DMARC`, `En-têtes`.
- Preuve : `À contrôler : DNS, signatures et en-têtes.`
- Continuité : le parcours sort de l’écran et entre dans l’infrastructure du courriel.
- Contraintes : authentification ne signifie pas garantie d’arrivée en boîte principale ; ne pas mettre SPF, DKIM et DMARC sous le mauvais contrôle.

### Slide 7 - Chaque envoi contient sa porte de sortie

- Rôle : rendre concrète la règle 174 dans un message reçu.
- Règle : 174, `Un lien de désinscription est présent dans chaque newsletter.`
- Scène : agrandissement du bas d’une newsletter, où `Se désinscrire` est lisible et activable ; plusieurs éditions empilées portent chacune le même repère.
- Texte : titre `Chaque envoi contient sa porte de sortie` ; labels `Chaque édition`, `Lien repérable`, `Lien actif`.
- Preuve : `À tester : le lien mène à une désinscription effective.`
- Continuité : après l’acheminement, l’abonné garde une issue dans chaque message.
- Contraintes : lien présent dans chaque édition ; ne pas assimiler visibilité et résultat du test.

### Slide 8 - Se désinscrire sans nouveau courriel

- Rôle : distinguer confirmation en ligne et demande d’un second courriel.
- Règle : 175, `La désinscription depuis une newsletter ne demande pas de confirmation par courriel.`
- Scène : comparaison de deux voies : formulaire de confirmation en ligne qui se termine ; boucle vers une boîte mail et attente, barrée en rouge.
- Texte : titre `Se désinscrire sans nouveau courriel` ; labels `Confirmation en ligne`, `Nouveau courriel`, `Attente`.
- Preuve : `Un écran en ligne est possible ; un courriel obligatoire ne l’est pas.`
- Continuité : précise ce qui se passe après le lien de sortie de la slide 7.
- Contraintes : ne pas montrer une désinscription automatique obligatoire au premier clic ; le formulaire en ligne est acceptable.

### Slide 9 - Trouver la sortie depuis le site

- Rôle : montrer que la sortie reste possible sans ancien message.
- Règle : 176, `La désinscription aux newsletters est possible depuis le site.`
- Scène : la navigation du site conduit à la page de gestion de newsletter puis à une confirmation de désinscription.
- Texte : titre `Trouver la sortie depuis le site` ; labels `Navigation`, `Gestion`, `Désinscription`.
- Preuve : `À tester : page trouvable et arrêt effectif des envois.`
- Continuité : la sortie passe de la boîte de réception au site.
- Contraintes : ne pas représenter la page comme cachée ou réservée à un compte ; le résultat doit être explicite.

### Slide 10 - Une sortie trouvable, sans détour inutile

- Rôle : respirer et synthétiser les règles 174, 175 et 176 sans créer une règle de symétrie.
- Scène : deux entrées sobres, `Newsletter` et `Site`, convergent vers `Désabonnement effectif` ; une confirmation en ligne facultative apparaît seulement sur le chemin issu du courriel ; beaucoup d’espace blanc.
- Texte : titre `Une sortie trouvable, sans détour inutile` ; labels `Newsletter`, `Site`, `Confirmation en ligne`, `Désabonnement effectif`.
- Callout : aucun.
- Continuité : ferme le bloc désinscription ; ouvre vers les contenus qui restent consultables.
- Contraintes : aucun badge de règle ; ne pas écrire que l’entrée et la sortie doivent être strictement symétriques.

### Slide 11 - La dernière édition est aussi en ligne

- Rôle : rendre la dernière édition consultable hors de la messagerie.
- Règle : 177, `La dernière newsletter envoyée est disponible en ligne.`
- Scène : une newsletter reçue et une page d’abonnement pointent vers le même aperçu Web clairement intitulé `Dernière édition`.
- Texte : titre `La dernière édition est aussi en ligne` ; labels `Depuis le courriel`, `Depuis l’abonnement`, `Dernière édition`.
- Preuve : `À vérifier : l’édition s’ouvre et se consulte réellement.`
- Continuité : après l’issue de service, le contenu lui-même devient retrouvable.
- Contraintes : une version Web ou un PDF consultable ; ne pas présenter une simple miniature comme contenu consultable.

### Slide 12 - Garder les anciennes éditions consultables

- Rôle : différencier la dernière édition des archives complètes.
- Règle : 178, `Les archives de newsletters sont disponibles en ligne.`
- Scène : vue en perspective d’archives ordonnées par date ; un seul exemplaire récent est isolé à côté d’un rayon vide.
- Texte : titre `Garder les anciennes éditions consultables` ; labels `Éditions envoyées`, `Archives`, `Dates`.
- Preuve : `À vérifier : les éditions envoyées restent accessibles.`
- Continuité : de l’édition courante à la mémoire du service.
- Contraintes : distinguer archive complète et quelques exemples ; ne pas inventer de dates ou de nombre d’éditions.

### Slide 13 - La newsletter ne vit pas seule

- Rôle : rappeler que les neuf règles ne forment pas un périmètre exhaustif.
- Scène : la page newsletter au centre d’un site vivant ; quatre zones voisines sont reliées sans badge de règle : formulaire, données personnelles, sécurité, contact.
- Texte : titre `La newsletter ne vit pas seule` ; labels `Formulaire`, `Données personnelles`, `Sécurité`, `Contact`.
- Callout : `Auditer aussi le parcours qui entoure la newsletter.`
- Continuité : agrandit le périmètre après l’étude des neuf règles dédiées.
- Contraintes : ces thèmes sont des dimensions transversales, pas une liste de règles exhaustive.

### Slide 14 - Relire le parcours avec VPTCS

- Rôle : appliquer les cinq attentes au même parcours concret.
- Scène : le trajet utilisateur apparaît en filigrane ; cinq fenêtres de lecture y pointent, sans soleil ni ampoules abstraites.
- Texte : titre `Relire le parcours avec VPTCS` ; labels `Visibilité - Où ?`, `Perception - Que comprendre ?`, `Technique - Est-ce fiable ?`, `Contenus - Que consulter ?`, `Services - Que gérer ?`.
- Callout : `VPTCS relit l’expérience dans son ensemble.`
- Continuité : les dimensions transversales deviennent cinq questions de relecture.
- Contraintes : les cinq initiales et libellés VPTCS présents une fois ; chaque question se rattache à une scène du parcours.

### Slide 15 - Cas pratique : auditez ce dossier

- Rôle : faire repérer les problèmes avant d’afficher les règles.
- Scène : dossier d’audit en trois surfaces voisines : formulaire de commande avec case cochée, aucun rythme annoncé et activation immédiate ; courriel reçu avec lien de sortie difficile à repérer et boucle de confirmation par courriel ; page Web sans dernière édition et avec archives vides.
- Transformation : l’auditeur relie plusieurs indices répartis entre écran, message et site.
- Texte : titre `Cas pratique : auditez ce dossier` ; question `Combien de problèmes repérez-vous ?` ; aucun numéro de règle.
- Continuité : prépare la correction et le tri des méthodes de vérification.
- Contraintes : sept anomalies visibles mais non annotées ; ne pas présenter ces trois surfaces comme une preuve suffisante de conformité technique ; aucune anomalie ne repose seulement sur la règle 217.

### Slide 16 - Observer ne suffit pas toujours

- Rôle : corriger le cas et trier les preuves nécessaires.
- Scène : trois postes d’audit distincts : écran et éditions à ouvrir ; parcours d’abonnement et de désinscription à tester ; configuration du domaine à contrôler.
- Texte : titre `Observer ne suffit pas toujours` ; groupes `Écran et éditions : 33, 179, 177, 178` ; `Parcours réel : 173, 174, 175, 176` ; `Technique : 217`.
- Question-callout : `La page suffit-elle pour vérifier l’authentification ? Non : DNS et en-têtes sont nécessaires.`
- Continuité : transforme les réponses du cas pratique en méthode d’audit.
- Contraintes : les neuf numéros sont placés dans la bonne catégorie et visibles une seule fois ; ouvrir réellement les éditions ; associer 217 au DNS et aux en-têtes ; aucune règle technique n’est déclarée vérifiée par une capture ; aucun domaine ni adresse de test inventés.

### Slide 17 - Retenir les neuf règles en trois temps

- Rôle : donner une carte mentale compacte.
- Scène : trois bandes temporelles, sans grille de neuf cartes : `Avant d’entrer` avec 179 et 33 ; `Pendant la relation` avec 173, 217, 174, 175 et 176 ; `Après l’envoi` avec 177 et 178.
- Texte : titre `Retenir les neuf règles en trois temps` ; afficher les neuf numéros une seule fois et des verbes courts.
- Callout : `Les numéros repèrent les règles ; le parcours aide à les retenir.`
- Continuité : synthétise le contenu avant l’action finale.
- Contraintes : chaque numéro présent une seule fois ; groupes avant, pendant, après dans cet ordre ; pas de texte secondaire long.

### Slide 18 - Testez le parcours de bout en bout

- Rôle : clôturer sur une action contrôlable.
- Scène : une adresse témoin traverse demande, confirmation, réception puis désinscription ; deux contrôles complémentaires apparaissent à côté : page des éditions et domaine d’envoi.
- Transformation : une suite de règles devient un test reproductible avec des preuves.
- Texte : titre `Testez le parcours de bout en bout` ; labels `Adresse témoin`, `Confirmer`, `Recevoir`, `Se désinscrire`, `Éditions en ligne`, `Domaine vérifié`.
- Callout : `Une adresse témoin. Un cycle complet. Des preuves.`
- Continuité : boucle vers le service complet présenté à l’ouverture, avec un geste à réaliser.
- Contraintes : ne pas réafficher la liste des sept stations ; ne pas prétendre qu’un seul test prouve toutes les règles.
