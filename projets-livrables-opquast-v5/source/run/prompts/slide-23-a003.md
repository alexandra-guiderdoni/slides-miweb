# Reprise image_gen - slide 23 - tentative a003

## Fiche PDS

- Rôle : bilan des trois études de cas avant l’inventaire des livrables.
- Idée principale : chaque règle exige l’observation d’un objet de contrôle précis.
- Scène : cinq cartes de contrôle convergent vers une boucle de responsabilités.
- Objet-système : cinq fiches numérotées et une boucle de gouvernance.
- Transformation visible : questions abstraites remplacées par les objets réellement contrôlés.
- Masque commun : en-tête, titre, badge, footer et pagination de la série.
- Image seule : comprendre que les cinq règles ne se vérifient pas sur le même support.
- Continuité : synthétiser les études de cas et préparer l’atlas des livrables.
- Risque : texte dense, formulation altérée, hiérarchie illisible ou faux logo.

## Prompt

Cas d’usage : productivity-visual.
Type d’actif : image finale de slide institutionnelle française, paysage 16:9.

Modifier la slide de référence en conservant strictement son identité visuelle :
fond blanc, bleu institutionnel, vert pâle réservé à la synthèse, panneaux très
clairs à bordure bleue fine, typographie Marianne avec fallback Arial, icônes
filaires sobres, beaucoup d’espace, aucune photographie, aucune 3D, aucun
dégradé, aucun blob, aucun faux logo.

Conserver exactement l’en-tête :
- haut gauche : `QUALITÉ WEB`, puis `EXPÉRIENCES DURABLES` ;
- haut droit : `Opquast`, puis `DES SITES MEILLEURS POUR TOUS` ;
- aucun symbole devant `Opquast`.

Titre aligné à gauche :
`Bilan : à chaque règle son objet de contrôle`

Créer cinq cartes lisibles organisées en deux rangées. Chaque carte présente le
numéro de règle en grand, son intitulé officiel, puis son objet de contrôle en
gras. Ne modifier aucun caractère des cinq intitulés :

1. `234`
   `Le contenu de chaque page est organisé selon une structure de titres et sous-titres hiérarchisée.`
   `Plan de titres HTML`
2. `77`
   `Chaque étiquette de formulaire est visuellement rattachée au champ qu’elle décrit.`
   `Affichage à l’écran`
3. `69`
   `Chaque champ de formulaire est associé dans le code source à une étiquette qui lui est propre.`
   `Association dans le code`
4. `85`
   `La soumission d’un formulaire est suivie d’un message indiquant la réussite ou non de l’action souhaitée.`
   `Parcours de soumission`
5. `222`
   `Le serveur envoie un code HTTP 404 pour les ressources non trouvées.`
   `Statut HTTP renvoyé`

Sous les cartes, placer une boucle horizontale sobre avec flèches et ces quatre
libellés exacts :
`Constat` → `Décision` → `Correction` → `Recontrôle`

Callout vert centré :
`La preuve vient de l’objet effectivement contrôlé`

Conserver exactement le bas de page :
- badge gauche : `ESSENTIEL 60` ;
- footer : `RÈGLES OPQUAST · PROJETS ET LIVRABLES` ;
- pagination droite : `23 / 45`.

Contraintes critiques : les cinq règles doivent être présentes une seule fois,
associées au bon objet de contrôle ; aucune question ouverte ; aucune réponse
inversée ; aucun texte tronqué, parasite ou inventé ; aucun paragraphe hors des
cartes ; aucun autre numéro de règle ; aucune faute d’accent ou d’apostrophe.
